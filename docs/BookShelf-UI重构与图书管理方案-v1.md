## 1. 字体：读中文看什么、读英文看什么

### 1.1 中文（阅读正文优先）

| 字体 | 风格 | 授权 | 体积 | 适用 |
|---|---|---|---|---|
| **霞鹜文楷 LXGW WenKai** | 楷体，笔画温润，长文最耐读 | OFL-1.1 | 20MB / 子集 3–6MB | **默认正文字体**，中文阅读首选 |
| **思源宋体 / Noto Serif SC** | 宋体，正式、书籍感强 | OFL-1.1 | 全量 20MB+ | 严肃读物、学术书 |
| **霞鹜新晰黑 LXGW Neo XiHei** | 黑体，屏幕优化，字重全 | OFL-1.1 | 约 8MB | 现代排版、年轻向内容 |
| **更纱黑体 Sarasa Gothic** | 中英等宽混排协调 | OFL-1.1 | 大 | 代码/技术书混排 |
| **思源黑体 / Noto Sans SC** | 无衬线，清晰 | OFL-1.1 | 大 | UI 与正文两用 |

> 方正、汉仪、汉仪旗黑这类**商用字体不要打包**——个人使用可以，随安装包分发属侵权。

### 1.2 英文

| 字体 | 风格 | 授权 | 说明 |
|---|---|---|---|
| **Literata** | Google Books 官方阅读字体，专为长文屏幕阅读设计 | OFL-1.1 | **英文默认首选**，字面开阔、不易累 |
| **EB Garamond** | 古典衬线，老书气质 | OFL-1.1 | 文学、经典 |
| **Source Serif 4** | Adobe 开源衬线，笔画干净 | OFL-1.1 | 学术、报告 |
| **Crimson Pro** | 紧凑衬线，排版密度好 | OFL-1.1 | 小说 |
| **Merriweather** | 大 x-height，低分屏也清楚 | OFL-1.1 | 网页/小屏 |
| **Inter** | UI 无衬线，数字友好 | OFL-1.1 | 只做界面，不做正文 |

> **Bookerly（Kindle 那款）和 Georgia 是专有字体，不能打包。** 想给用户"Kindle 那种感觉"，用 Literata 最接近且合法。

### 1.3 落地方式

1. 目录：`app/reader/assets/fonts/`（现在**不存在**，先建）。放 4 个文件即可起步：
   `LXGWWenKai-Regular.ttf`、`Literata-Regular.ttf`、`SourceSerif4-Regular.otf`、`Inter-Regular.ttf`。
2. 中文宋体用**子集**：`pyftsubset SourceHanSerifSC-Regular.otf --unicodes="U+0020-007E,U+3000-303F,U+4E00-9FFF,U+FF00-FFEF"`，能把 20MB 压到 6–8MB；MEMORY 里再留一份完整版供"高质量模式"可选下载。
3. `reader.css` 顶部 `@font-face` 声明（`font-display: swap`）；`reader.js:295` 的 `font-family` 直接写声明过的 family 名。
4. 设置里的字体下拉 = **扫描目录得到的实际文件 + `QFontDatabase.families()` 系统字体**，每项标注「内置 / 系统」。**绝不显示一个没装的字体名。**
5. 打包：`BookShelf.spec` 的 `datas` 必须包含 `app/reader/assets`（已包含，但要确认 `fonts/` 递归进去），安装后位于 `_internal/app/reader/assets/fonts`。
6. **内置字体不可从 UI 删除**（设置页只读展示"内置 4 个 / 6.8MB"）。用户自装字体放 `%APPDATA%\BookShelf\fonts\`，那一层才允许删除。

### 1.4 空目录清理（你提的那个入口）

书库里常有 calibre 留下的空文件夹（比如只删了书没删目录）。做一个独立动作，不混进"整理"：

- 位置：左导航「工具 → 清理空目录」或整理下拉里的「清理空文件夹」。
- 规则：**只扫描受管目录**（库根 `library_root` + 归档目录），深度不限；目录内只有 `.DS_Store`/`Thumbs.db`/`desktop.ini` 视为空；**删除前预览列表**，默认勾选，可取消；移到回收站而不是直接删。
- 安全：绝不触碰"原始导入目录"（`source_dirs` 白名单），路径不在受管根下的直接跳过。
- 日志：写 `operations`，可撤销（回收站恢复）。

## 2. Calibre 是怎么管书的（决定我们选哪条路）

### 2.1 Calibre 的实际机制

| 环节 | Calibre 做法 |
|---|---|
| 加书 | **复制**文件进库，原文件不动（"Add books" 默认就是 copy；有 move 选项但很少用） |
| 库结构 | `作者/书名 (自增id)/` 每本书一个目录 |
| 文件名 | `书名 - 作者.epub`（可配模板）；**同一本书的多格式放同目录**（`.epub` `.pdf` `.mobi`） |
| 元数据 | 每书目录里生成一份 `metadata.opf`（字段快照，便于脱离库恢复）；主库是 `metadata.db`（SQLite） |
| 改名/整理 | 只发生在库内，模板变更时全库重算路径 |
| 导出 | `Save to disk` 按模板导出到外部目录，**不改库** |
| 删除 | 进 `.trash` / 系统回收站，可恢复 |
| 转换 | `ebook-convert`，产出**新格式文件**并排在原书目录里，原文件保留 |

### 2.2 四条路线对比

| 方案 | 说明 | 优点 | 缺点 |
|---|---|---|---|
| A 链接（只记录路径） | 书库只存 `F:\E-book\xxx.epub` 的路径 | 零磁盘占用、不重复 | 源目录一动书就"失联"；改名就得改原文件；多盘迁移全崩 |
| B 复制入库 + 重命名（**Calibre 路线**） | 拷进 `library_root/作者/书名 (id)/`，按模板命名 | 库自洽、可重建、可导出、源文件安全 | 占双份空间；首次导入慢 |
| C 移动入库 | 直接挪走源文件 | 不占双份 | **危险**：源目录被掏空，用户后悔难恢复 |
| D 混合 | 默认复制，加"仅登记不复制"开关给大文件 | 灵活 | 两套路径语义，容易混 |

**建议：B 为主 + D 的开关。** 你现在的代码已经是这个思路（`organize_service` 默认复制、`undo` 可回滚），不要改成 A——A 在 1872 本这种规模上维护成本极高，而且你已经有"原始导入目录不能动"的明确要求，B 正好满足：**源目录只读，库内可任意改名/移动**。

需要补三件 Calibre 有而我们没有的：

1. **每书写一份 `metadata.opf`**（`库内/作者/书名 (id)/metadata.opf`）：库迁到别的机器、SQLite 丢失时，可以"从文件重建库"。字段与 `books` 表一一对应，`json.dumps(ensure_ascii=False, indent=2)` + OPF 骨架二选一（建议直接写 OPF，方便未来导入 calibre）。
2. **同书多格式合目录**：`book_id` 相同的不同格式落在同一目录，文件名主体一致、扩展名不同。
3. **`id` 兜底重名**：`书名 (2185)` 这种 calibre 目录名保留为兼容形态；我们自己的命名用 `书名 (id)` 也行，关键是**同一作者下同名书必须唯一**。

现状问题：一排 5 个平级按钮（扫描新书/选择书库/识别元数据/预览整理/执行整理）权重相同、语义混杂（"选择书库"是配置，"执行整理"是危险操作）；左侧导航 3 组 8 项全是文字、无图标、无分组标题；右侧详情只读且大量"——"。

### 3.1 顶栏（48px，通体一色）

| 区 | 元素 |
|---|---|
| 左 | `☰` 折叠左导航（<1200px 自动折叠）、应用名「书格」、当前库名小字 |
| 中 | 搜索框（宽 320，占位"书名 / 作者 / ISBN"，右侧 `⌘K` 提示） |
| 右 | 「＋ 添加书籍」主按钮（accent）→ 下拉：扫描目录 / 选择文件 / 拖拽提示；`⋯` 更多（导入 calibre 库、从文件重建库、备份）；主题切换（☀/☾）；设置齿轮 |

**"选择书库""设置""帮助"全部收进 `⋯` 和齿轮，不要占主工具栏。** 这些是低频操作，摆在第一排只会稀释主操作。

### 3.2 工具栏（56px）= 状态摘要 + 视图控制

现在是"5 个动作按钮"，改成一个**计数条 + 两个控件**：

- 左：三段计数 `全部 1,872 / 已识别 1,748 / 待整理 124`（点击即筛选，当前项加下划 accent）；
- 右：视图切换（4 个 24px 图标的分段控件）、排序下拉（`书名 / 添加时间 / 文件大小 / 识别度`）。

**"识别元数据""预览整理""执行整理"不放到这一行**，而放到：
- 「识别元数据」→ 选中多本后出现的**浮动批量条**（见 3.5），或右键菜单；
- 「预览/执行整理」→ 左导航「工具 → 整理」进入**独立的整理工作区**（有预览表、目标路径列、冲突提示），而不是在主列表上点按钮就直接动文件。

危险操作（批量移动、删除、执行整理）一律在**独立页面 + 顶部警示条**里完成，这是 Calibre 的做法（它有单独的"Convert"和"Save to disk"对话框，绝不混在列表工具栏）。

### 3.3 左导航（宽 216，可折叠到 0）

| 分组 | 项 | 说明 |
|---|---|---|
| （无标题）书库 | 全部书籍 / 待整理 / 已归档 / 识别失败 | 带计数徽标；「识别失败」为 0 时灰显 |
| 分类 | 作者 / 系列 / 文件夹 / 标签 / 收藏 | 图标 + 文字，二级展开（作者页已有现成布局） |
| 工具 | 整理（预览+执行）/ 清理空目录 / 回收站 / 格式转换 / 备份 | 低频，放最下 |

规则：**一级项高 40，二级缩进 28；分组之间 16px 分隔 + 小标题 11px muted**；选中项左侧 3px accent 竖条 + 浅底。图标统一 16px 线性（已有 `resources/icons` 里的 SVG，补 6 个：整理、清空、回收站、转换、备份、主题）。

### 3.4 主列表（列表视图）

- 行高 44（比现在 34 高，容纳 28×40 缩略封面）；
- 列：`☐ | 封面 | 书名(可省略) | 作者 | 格式徽标 | 卷 | 状态徽标 | 大小 | 添加时间`；
- 状态徽标配色：已识别=绿点、待确认=琥珀、失败=红、DRM=灰；
- 悬停显示两个小按钮（右侧）：打开 / 详情；单击行 = 右侧详情刷新，双击 = 打开阅读。

### 3.5 批量浮动条（选中后从底部升起）

```

│ 重新识别   移动到…   复制到…   导出为…   删除   取消选择 │

```

- 「移动到…」= 在**受管库内**换目录（改 `library_root` 下的相对路径，安全，可撤销）；

## 4. 格式转换：要做，但只做安全的四种

**不要**做 PDF→EPUB/Word（PyMuPDF、pdfplumber 都是 AGPL，且效果差、重排必崩）。

建议支持（全部纯 Python、许可干净）：

| 方向 | 方案 | 说明 |
|---|---|---|
| MOBI / AZW3 → EPUB | 已有 `app/reader/mobi.py`（自研），复用 | 现成，只是把"阅读时转换"提到"转换功能" |
| EPUB → EPUB（清洗） | 自研 zip 重写：去 DRM 外字体混淆、修 container 大小写、补 OPF 字段 | 和 S1 的容错共用一套代码，顺手就能"修复结构" |
| EPUB → TXT / HTML（单文件） | 自研：按 spine 顺序拼正文 | 简单，适合导到手机/剪藏 |
| EPUB → PDF | 用 QtWebEngine 打印（`QWebEngineView.printToPdf`） | 需要逐章渲染，慢但可控；列为可选 |
| 任意 → 任意（重排） | **检测到本机已装 Calibre 时，调用 `ebook-convert`** | 不打包、不依赖，用户自己有才用 |

UI：左导航「工具 → 格式转换」→ 独立页，左边源文件列表、右边目标格式 + 选项（"保留原文件 / 替换"），底部"开始转换"，进度条 + 完成后"在库内新增副本"。**转换结果永远生成新文件，不覆盖原件**（与 Calibre 一致）。

### 验收
